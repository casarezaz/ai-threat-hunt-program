## Hypothesis

At least one application path returns retrieval results without the per-user metadata filter being applied — or the filter disagrees with the source-system ACL.

## Why this matters

Authorization at retrieval time is the central RAG control (Paper 3). A single application path that bypasses the filter (debug endpoint, admin path, agent tool call, batch job) makes every other control vacuous.

## Data sources

- Retrieval logs (must include filter inputs and the filter that was applied)
- Source-system ACL data
- Application path identifier (UI / debug / admin / agent / batch)

## Detection logic

See Paper 3 §RAG-002. Summary: for each retrieval event, alert when no metadata filter was applied OR when the applied filter results disagree with a source-side authorization check on at least one returned chunk.

## Evidence to capture

- Identity, application path, top-k, chunk IDs, source document IDs
- Filter expression actually evaluated by the index
- Source-system authorization decision per chunk
