## Hypothesis

A query in Tenant A returned a chunk whose tenant metadata is Tenant B.

## Why this matters

In a multi-tenant RAG, this is the highest-severity authorization failure: customer data crossing the customer boundary inside an "internal" system. Any non-zero count is a board-level conversation.

## Data sources

- Retrieval logs with requester tenant + per-chunk tenant metadata
- Tenant registry

## Detection logic

See Paper 3 §RAG-005. Summary: every retrieval whose chunk-tenant metadata does not match the requester-tenant is a critical alert.

## Evidence to capture

- Identity and requester tenant
- Chunk IDs and chunk tenants
- Whether the leak chunks reached the model and the user
