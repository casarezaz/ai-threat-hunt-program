## Hypothesis

Retrieval returned a chunk whose source ACL has tightened since ingestion, and the index still treats the requester as authorized.

## Why this matters

The most common and most-overlooked RAG leak. A document was made restricted three months ago, the index still has it indexed under the old ACL snapshot, and nothing reindexes on ACL change.

## Data sources

- Retrieval logs with chunk-level ACL snapshot at ingest
- Source-system current ACL data
- Reindex job history (so we can tell whether the chunk should already have been refreshed)

## Detection logic

See Paper 3 §RAG-006. Summary: for each returned chunk, compare the requester against the *current* source ACL; alert when the requester is no longer authorized but was at ingestion time.

## Evidence to capture

- Chunk ID, source document ID
- ACL snapshot at ingest vs. current ACL
- Last reindex timestamp for the chunk
- Whether the answer to the user used this chunk
